# Дайджест Cloud.ru: bootstrap

Локальный Python CLI строит объяснимый дайджест по простым правилам. Это начальный прототип, не финальное решение кейса. Runtime использует только стандартную библиотеку Python 3.11+. Нет сети, LLM, интеграции Brand Analytics, сервера, БД или UI.

В `demo/` находятся только синтетические сообщения с адресами example.invalid. Реальных выгрузок и golden нет; качество на реальных данных не измерено.

## Установка и демонстрация

Из корня репозитория в PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -B -m cloud_digest --input demo/messages.json --date 2026-10-27 --output-dir results --top-n 30 --synthetic
```

Установка зависимостей может требовать доступ к индексу пакетов; обработка файлов полностью локальна. Для POSIX используйте `python3 -m venv .venv` и `.venv/bin/python` вместо Windows-пути. Секреты и настройки провайдера не нужны.

Ожидаются четыре карточки и два файла: `results/digest-2026-10-27.json` и `results/digest-2026-10-27.txt`. JSON содержит `synthetic: true`, текст — «СИНТЕТИЧЕСКИЙ ПРИМЕР — ВЫМЫСЕЛ». Повторите команду с `demo/messages.csv` и другим выходным каталогом: результат идентичен. Флаг `--synthetic` нужно передавать явно, CLI не определяет вымысел самостоятельно.

`--date` — сутки МСК (UTC+03:00), строго YYYY-MM-DD; `--top-n` — 1–30 (по умолчанию 30). Повторный запуск заменяет выходные файлы. Код возврата 0 означает созданный результат (включая пустой день), 2 — ошибку аргументов/валидации, 1 — ошибку чтения/записи или внутреннюю ошибку. При ошибке не считайте прежние файлы новым результатом: запись двух файлов не атомарна.

## Контракт файлов

Вход: UTF-8 или UTF-8-BOM, JSON-массив объектов либо CSV с заголовком и разделителем-запятой. Обязательные непустые строки: `message_id`, `published_at`, `source_type`, `source_name`, `url`, `text`. ID уникален во всём файле; время ISO 8601 содержит `T` и часовой пояс; URL — http/https с hostname, ссылки не открываются.

Необязательные строки: `author_name`, `author_id`, `language`, `geo`, `ba_topic_hit`. Метрики `audience`, `views`, `likes`, `comments`, `reposts` — целые ≥0 либо null; bool и дроби запрещены. Неизвестный audience остаётся null, а не нулём. `ba_sentiment`: negative/neutral/positive, −/-/0/+ либо null (числовой JSON 0 допустим). Пустые необязательные CSV-ячейки означают неизвестное значение. Неизвестные поля игнорируются с предупреждением. Валидируется весь вход, включая строки вне выбранного дня. Пустой массив и CSV только с корректным заголовком допустимы; пустой файл — ошибка.

Выход: `digest_date`, `rule_version`, `summary_counts`, `items` (до 30), `dropped_examples` (до 10), `risk_alert`, `risk_alert_details`, `review_queue`, `empty_message`, `synthetic`. Карточки содержат исходные ID/дату/источник/URL/audience/BA-тональность, вычисленные тональность и важность с объяснением, связь с брендом и цитату, кластер и его размер, выдержку, рекомендацию и признаки ручной проверки. Очередь проверки может включать записи вне top-N и дубли. Отсутствие кандидатов даёт строку «Прямого или косвенного упоминания Cloud.ru не найдено»; это не доказательство отсутствия косвенных связей.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m mypy src
.\.venv\Scripts\python.exe -m compileall -q src
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m build --wheel
```

18 синтетических тестов покрывают валидацию, границы суток, дубли, бренд, риск и top-N. Они не оценивают качество на реальных сообщениях.
