# Cloud Digest — умный отбор упоминаний Cloud.ru

Локальное Python-приложение: принимает публикации из JSON/CSV или партнёрской выгрузки, находит упоминания Cloud.ru, объединяет сообщения в информационные сюжеты, рассчитывает приоритет и формирует **JSON + TXT дайджест**.

**Статус:** работающий исследовательский прототип (8 этапов реализованы в коде), **не промышленный MVP**. Формулы скоринга и распознавание фактов эвристические; качество семантической модели на реальных данных пока не подтверждено эталонной разметкой.

**Навигация:** [быстрый запуск](#быстрый-запуск-windows) · [веб-панель и инструкция](#веб-панель-cloud-digest-editor-streamlit) · [архитектура](#как-устроена-программа) · [этапы](#что-реализовано-по-этапам) · [технологии](#технологии).

## Быстрый запуск (Windows)

Открой CMD или терминал VS Code **в корне репозитория** — там, где лежит `pyproject.toml`. Python: **3.11+** (в том числе 3.12).

```cmd
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Простой запуск на реальной партнёрской выгрузке (Story Score **без** embeddings):

```cmd
.\.venv\Scripts\python.exe -m cloud_digest --input "partner_data\Очищенная выгрузка 26-31.08.json" --partner-export --date 2026-08-31 --output-dir "results\story" --scoring story-v1
```

Результат: `results/story/digest-2026-08-31.json` и `.txt`. Дата задаётся по **московскому времени (UTC+03:00)**.

Чтобы включить **семантическую кластеризацию** (при первом запуске модель скачивается, нужен интернет):

```cmd
.\.venv\Scripts\python.exe -m pip install -e ".[embeddings]"
.\.venv\Scripts\python.exe -m cloud_digest --input "partner_data\Очищенная выгрузка 26-31.08.json" --partner-export --date 2026-08-31 --output-dir "results\semantic-story" --scoring story-v1 --clustering semantic --embedding-device cpu
```

**Без выгрузки** можно запустить синтетический пример:

```cmd
.\.venv\Scripts\python.exe -m cloud_digest --input demo/messages.json --date 2026-10-27 --output-dir results\demo --synthetic
```

Для macOS/Linux вместо `.\.venv\Scripts\python.exe` используй `.venv/bin/python`; создание окружения: `python3 -m venv .venv`.

**Вариант в один клик:** `RUN_WINDOWS.bat` запускает обработку 26–31 августа (по умолчанию `story-v1` без embeddings). `RUN_WINDOWS.bat baseline` — старые правила, `RUN_WINDOWS.bat semantic` — Story Score с семантической моделью. Результаты пишутся в `results/`, а не поверх исходных `partner_results/`.

## Веб-панель Cloud Digest Editor (Streamlit)

**Для кого:** аналитик или редактор, которому нужно получить дайджест из выгрузки Brand Analytics (BA), посмотреть приоритеты сюжетов, проверить спорные случаи и сохранить решения. Интерфейс работает локально в браузере и использует тот же Python-движок, что и CLI; **он не заменяет Brand Analytics**.

### Запуск в Windows за три шага

Открой **CMD в корне проекта** (`outputs\repo`, где лежат `pyproject.toml` и `RUN_DASHBOARD_WINDOWS.bat`):

```cmd
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[ui]"
RUN_DASHBOARD_WINDOWS.bat
```

После запуска открой **http://127.0.0.1:8501**. Если при первом запуске Streamlit предложит указать Email, можно оставить поле пустым и нажать **Enter**. Не закрывай окно терминала, пока пользуешься панелью; для завершения нажми **Ctrl+C**.

Чтобы включить *семантическое* объединение пересказов (embeddings), один раз установи дополнительные зависимости в **то же** окружение:

```cmd
.\.venv\Scripts\python.exe -m pip install -e ".[ui,embeddings]"
```

При первом включении embeddings загружаются веса модели; потребуется доступ к сети. Для первого знакомства с интерфейсом **оставь переключатель embeddings выключенным** — базовая кластеризация и Story Score работают без ML-зависимостей. Для macOS/Linux: `python3 -m venv .venv`, затем `.venv/bin/python -m pip install -e ".[ui]"` и `.venv/bin/python -m streamlit run ui/app.py`.

### Как обработать собственные публикации

1. В левой колонке раскрой **«Сформировать новый дайджест»**.
2. В поле **«Загрузить свой датасет BA / Cloud Digest (.json, .csv)»** выбери файл с *исходными публикациями*. Вместо загрузки файла можно использовать **«Или выбрать локальную выгрузку»** из папки `partner_data/`. Если загружен свой файл, при обработке используется **он**, а не пункт выпадающего списка.
3. В поле **«Дата дайджеста»** выбери дату, за которую нужны публикации. Дата отбора интерпретируется по **московскому времени**. Для комплектной выгрузки можно попробовать `2026-08-31`.
4. В поле **«Скоринг»** выбери **`story-v1`** (рекомендуется для панели). Режим `publication-v2` оценивает отдельные публикации, `baseline` нужен для сравнения со старой версией.
5. На первом запуске **выключи «Семантическая кластеризация (embeddings)»**. Для анализа пересказов потом включи этот переключатель и повтори обработку.
6. Нажми **«Обработать выгрузку»**. Созданный дайджест автоматически откроется справа; в верхней части появятся кнопки скачивания.

**Важно: не путай два поля загрузки.** Поле **«Загрузить готовый дайджест (.json)»** вверху панели принимает *уже обработанный* `digest-YYYY-MM-DD.json`, который можно открыть без повторного запуска алгоритма. Исходный `Очищенная выгрузка 26-31.08.json` нужно передавать **только** через поле загрузки датасета в блоке обработки. Если загрузить его как готовый дайджест, появится ошибка «JSON не является дайджестом Cloud Digest».

**Поддерживаемые входные форматы:**

| Формат | Требования |
|---|---|
| Исходный JSON Brand Analytics | Непустой массив публикаций с полями `id`, `timeCreate`, `url` и другими данными экспорта BA |
| Нормализованный JSON Cloud Digest | Непустой массив объектов с `message_id`, `published_at`, `source_type`, `source_name`, `url`, `text` |
| Нормализованный CSV Cloud Digest | Те же шесть обязательных колонок, UTF-8 |
| Готовый `digest-*.json` | Только для поля **«Загрузить готовый дайджест»**, без повторной обработки |

Размер исходного датасета — **до 30 МБ**. Произвольный CSV с другими названиями столбцов сначала нужно привести к формату Cloud Digest. Файлы `brand_dictionary.json` и `top25_sources.json` — это **справочники**, а `golden_set_26_31_aug.json` — **редакторская подборка, не проверенный Golden set**; их не нужно загружать как обычные новости.

### Что можно делать в панели

| Раздел | Возможности |
|---|---|
| **Лента сюжетов** | Поиск по сюжету/источнику, фильтр по статусу, минимальному баллу, выбор карточки |
| **Карточка сюжета** | Тема, основная публикация и ссылка на неё, Story Score, число публикаций, текстовая выжимка |
| **«Почему такой приоритет»** | Разбивка начисленных баллов, сравнение тональности BA и Cloud Digest, основания для проверки |
| **«История сюжета»** | Публикации и источники внутри кластера: время, ссылка, аудитория, индивидуальный балл |
| **Очередь первичной проверки** | Сообщения, помеченные движком как спорные, в том числе за пределами top-N |
| **«Правка редактора»** | Подтверждение / исключение сюжета, правка отображаемой тональности и связи с брендом, своя выжимка, комментарий, заявка на объединение / разделение кластеров |

Чтобы сохранить редакторское решение, открой сюжет → вкладка **«Правка редактора»** → выбери поля → нажми **«Сохранить решение»**. После сохранения статус обновится, а изменения попадут в редакторский экспорт. Заявки на объединение/разделение кластера пока **не выполняются автоматически**.

### Где результаты и как их скачать

После успешной обработки оригинал загруженного датасета и готовый дайджест сохраняются **на твоём компьютере**:

```text
results/ui/uploads/                                      # загруженные исходные файлы
results/ui/<тип-кластеризации>/<дата>/<скоринг>/<хеш>/
    digest-YYYY-MM-DD.json                               # машинный результат
    digest-YYYY-MM-DD.txt                                # читаемый дайджест
artifacts/editor_reviews.json                            # локальные правки редактора
```

Чтобы получить результат именно в браузерную папку **«Загрузки»**, нажми **«Скачать JSON»**, **«Скачать TXT»** или **«Скачать всё ZIP»** над карточками. TXT и ZIP доступны, когда у открытого результата есть соответствующий TXT на диске (например, после обработки). Для редакторских решений отдельно нажми **«Скачать редакторский JSON»** внизу страницы. Браузер не может автоматически помещать файлы в «Загрузки» без действия пользователя.

### Частые вопросы и ошибки

- **«Streamlit is not installed»** — установи `.[ui]` именно в `.venv`: `.\.venv\Scripts\python.exe -m pip install -e ".[ui]"`. Скрипт запуска использует этот интерпретатор, а не обязательно глобальный `python`.
- **«JSON не является дайджестом Cloud Digest»** — исходную выгрузку BA загрузили в поле *готового* дайджеста. Удали файл из этого поля и используй **«Сформировать новый дайджест»**.
- **Нужны embeddings / ошибка их импорта** — установи `.\.venv\Scripts\python.exe -m pip install -e ".[ui,embeddings]"` или временно отключи семантическую кластеризацию.
- **После обработки нет публикаций** — проверь дату (отбор по московскому времени), формат входного файла и наличие упоминаний Cloud.ru.
- **Не появилась кнопка TXT/ZIP** — у выбранного *готового загруженного* JSON может не быть парного TXT; обработай исходные сообщения через панель или открой сохранённый локальный результат.
- **Правка не меняет балл** — это текущее ограничение: редакторское решение сохраняется отдельно, но алгоритм не пересчитывает Story Score при изменении тональности.

### Связь с Brand Analytics и ограничения

Сейчас интеграция реализована через **локальные выгрузки BA**, без прямого подключения к API. Исходные сообщения BA не редактируются; правки хранятся отдельно в `artifacts/editor_reviews.json` и могут экспортироваться. **Обратная запись в BA, многопользовательская работа, права доступа и автоматическое переобучение не реализованы.** Считай Story Score оценкой *приоритета сюжета*, а не точным измерением уникальной аудитории. Не публикуй реальные партнёрские данные и журнал редактора в общедоступном Git-репозитории.

Дополнительные технические детали и схема движения данных — в [документации панели](docs/DASHBOARD.md).

## Как устроена программа

```text
JSON / CSV / партнёрская выгрузка
       │
       ▼
validation.py + partner.py      проверка полей и адаптация
       │
       ▼
preprocessing.py                очистка текста, бренд, заголовок
       │
       ▼
clustering.py                   объединение публикаций в сюжеты
       ├── baseline: текст/хеш
       └── semantic: embeddings.py + event_facts.py
       │
       ▼
scoring.py                      оценка каждой публикации
source_authority.py             авторитетность площадки и top-25
       │
       ▼
story_scoring.py                общий приоритет сюжета
       │
       ▼
digest.py + story_view.py       top-N, карточки, история, JSON/TXT
```

`core.py` — **совместимый интерфейс старого кода**, а не место, где теперь сосредоточена бизнес-логика. `cli.py` управляет режимами запуска. Полная карта модулей и ограничений — в [архитектуре](docs/Architecture.md).

## Что реализовано по этапам

| Этап | Результат |
|---|---|
| 01. Рефакторинг | Логика разделена на модули |
| 02. Подготовка | Очистка и проверка входных данных без потери оригиналов |
| 03. Embeddings | Пакетная векторизация, локальный кэш, отдельная CLI-команда |
| 04. Кластеризация | Два порога сходства, совместимость событий, отдельный RSS-поиск кандидатов |
| 05. Publication Score | Оценка публикаций, веса и top-25 площадок из `partner_data/top25_sources.json` |
| 06. Story Score | Учёт поздних репостов, новых фактов и ограниченного бонуса охвата |
| 07. Дайджест | Одна карточка сюжета, главный источник, история распространения |
| 08. Оценка | Метрики кластеризации/ранжирования, шаблон gold-разметки, калибровка dev/test |

Это **наличие функциональности**, а не доказательство точности алгоритмов. План доведения до полноценного MVP — в [ROADMAP](docs/ROADMAP.md).

## Актуальные метрики и Golden set (07.11.2026)

**Последняя версия разметки — `gold/2026-08-31_reaudit_DRAFT.json`.** После повторного аудита размечено 169 сообщений (в оценщик входят 154 кандидата), 27 значений `relevance` исправлены, 60 записей отмечены для проверки. Отдельно различаются внешние новости, собственные публикации Cloud.ru, комментарии и репосты.

**Результаты baseline на разметке DRAFT:** Pairwise F1: 3,17% (`dev`) и 50,00% (`test`); B-cubed F1: 15,79% и 75,38%. При `story-v1` на прежних baseline-кластерах Recall@30: 33,33% (`dev`) и 66,67% (`test`); NDCG@30, рассчитанная только по размеченным карточкам: 86,09% и 78,37%. Последние показатели изменились после пересмотра релевантности.

**Это не финальные и не независимые метрики:** статус Golden set — `draft`, ни одна из 169 строк ещё не подтверждена редактором, и качество `semantic` на обновлённом наборе не измерено. Результаты по критическим событиям также не определены. Не использовать старый `gold/2026-08-31_seed_DRAFT.json` (25 записей) и прежние сравнительные цифры как актуальный отчёт. Подробности — [METRICS_CURRENT](docs/METRICS_CURRENT.md).

## Режимы и дополнительные команды

- `--scoring baseline` (по умолчанию): старый воспроизводимый baseline; `--scoring publication-v2`: оценка публикаций; `--scoring story-v1`: оценка сюжетов и удобный TXT.
- `--clustering baseline` (по умолчанию): старое хеш-объединение; `--clustering semantic`: эмбеддинги + пороги `--similarity-high` / `--similarity-low` (по умолчанию 0.88 / 0.78; **не откалиброваны**).
- Экспорт векторов: `python -m cloud_digest.embedding_cli --help`.
- Дополнительные RSS-кандидаты: `python -m cloud_digest.candidate_cli --help`. Флаг `--internet` включает внешние запросы; найденные материалы идут **на проверку**, а не сразу в основной дайджест.
- Метрики и разметка: `python -m cloud_digest.evaluate_cli --help`. Файл `gold/2026-08-31_seed_DRAFT.json` — **черновик**, его результаты нельзя выдавать за подтверждённую оценку качества.
- Справочники и веса: `config/publication_scoring_v2.json` и `config/story_scoring_v1.json`. Пути по умолчанию относительные: запускай команды из корня проекта.

## Технологии

**Язык:** Python 3.11+. **Упаковка:** setuptools, `pyproject.toml`. **Встроенные библиотеки:** `argparse`, `json`, `csv`, `datetime`, `hashlib`, `urllib`, `unittest` и др. **Локальная панель:** Streamlit (extra `ui`). **Опциональный ML:** `sentence-transformers` (и его зависимости, в том числе PyTorch) для многоязычных embeddings. **Проверки разработки:** `unittest`, `mypy`, `build` (два последних — опциональный extra `dev`).

Есть локальная Streamlit-панель редактора; нет БД, расписания автоматического запуска и промышленной двусторонней интеграции с Brand Analytics. Основная обработка локальна; загрузка весов модели и RSS-поиск могут требовать сеть.

## Ограничения и безопасность

- Тональность и часть «фактов» определяются правилами; проверка **совместимости** фактов не равна проверке их **истинности**.
- `Story Score` — объяснимый **приоритет**, а не измеренный уникальный охват: аудитории могут пересекаться.
- Сильные источники оцениваются по настраиваемой **экспертной эвристике**, не по официальному рейтингу достоверности.
- Для публикации результатов в открытом GitHub **не загружай** реальные партнёрские выгрузки, их копии, кэш эмбеддингов и внутренние материалы. В переданном архиве `partner_data/` и `partner_results/` уже содержат реальные данные — проверь доступы.
