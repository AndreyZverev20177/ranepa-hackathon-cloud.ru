# Baseline-v1 и Semantic: сравнение одной и той же задачи

Этот патч **не меняет алгоритмы, настройки скоринга или рабочую панель**. Он добавляет воспроизводимый запуск и отчет на одинаковых входных публикациях и на одной разметке.

## Установка

Распакуйте ZIP в корень `outputs\repo`. Папки `tools/`, `gold/`, `docs/` и файл `RUN_COMPARE_WINDOWS.bat` окажутся внутри репозитория.

**Внимание:** `gold/2026-08-31_auto_DRAFT.json` содержит не подтвержденные человеком метки и выдержки из партнерской выгрузки. Используйте в закрытом репозитории; не публикуйте в открытом GitHub. После проверки исходного Excel замените этот файл в вызове на свой `verified` JSON.

## 1. Первый сравнительный прогон (одинаковые пороги)

Из `outputs\repo` в CMD:

```cmd
.\.venv\Scripts\python.exe -m pip install -e ".[embeddings]"
RUN_COMPARE_WINDOWS.bat
```

Первые 150+ новостей могут потребовать скачать модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`. Параметр `--embedding-device cpu` обеспечивает работу без GPU.

Получите:

- `results/model_comparison/evaluation_fixed_thresholds.json` — расчет оценщика (baseline и semantic в одном JSON);
- `results/model_comparison/baseline_vs_semantic.md` — сравнение метрик;
- `results/model_comparison/baseline_vs_semantic.csv` — таблица для Excel.

Второй аргумент позволяет подставить проверенный файл: `RUN_COMPARE_WINDOWS.bat "gold\verified.json"`.

## 2. Подбор порогов только по dev

После первого прогона и **ручной проверки разметки**:

```cmd
.\.venv\Scripts\python.exe -m cloud_digest.evaluate_cli --input "partner_data\Очищенная выгрузка 26-31.08.json" --partner-export --date 2026-08-31 --gold "gold\verified.json" --semantic --calibrate --high-grid 0.80,0.84,0.88,0.92 --low-grid 0.68,0.72,0.78,0.82 --min-precision 0.90 --embedding-device cpu --output "results\model_comparison\evaluation_calibrated.json"
.\.venv\Scripts\python.exe tools\compare_report.py --report "results\model_comparison\evaluation_calibrated.json" --output-prefix "results\model_comparison\calibrated_comparison"
```

Если ни один порог не прошел заданный Precision на dev, оценщик **не возвращает итоговые semantic-метрики**; это результат эксперимента, а не ошибка отчета. В таком случае изучите dev precision/recall и расширьте обучающую разметку.

## 3. Что сравниваем

| Показатель | Смысл |
| --- | --- |
| Pairwise Precision | Доля правильных объединений среди автоматически объединенных пар |
| Pairwise Recall | Доля реально одинаковых пар, которые смогли объединить |
| Pairwise F1 | Сбалансированное качество кластеризации по парам |
| B-cubed F1 | Качество кластеризации по публикациям; меньше зависит от размеров гигантского сюжета |
| Ложные объединения | Сколько пар разных событий попали в один кластер |
| Пропущенные совпадения | Сколько пар одного события оказались в разных кластерах |
| Story Recall@30 | Сколько значимых размеченных сюжетов обнаружено среди 30 карточек |
| NDCG@30 (judged-only) | Качество порядка *только тех карточек*, для которых есть разметка |

При сравнении ранжирования формула `story-v1` в обоих режимах **одинакова**. Меняется только способ кластеризации.

## 4. Критические ограничения данной выборки

- Golden set содержит 154 предварительно размеченные записи; 119 относятся к одному финансовому сюжету.
- `dev` содержит 127 сообщений, `test` — 27. Разделение сделано по сюжетам и не дает утечки одинаковых статей, но группы существенно различаются по размеру и типам.
- Все `critical=false`, поэтому оценить пропуск кризисов на этой дате **невозможно**.
- 15 публикаций, не прошедших фильтр бренда, не оцениваются этим сравнением кластеризации; их проверяют отдельным тестом `brand_gold`.
- Текстовая разметка `DRAFT` получена автоматически и должна быть проверена человеком. До проверки метрики нельзя заявлять как подтвержденные.
- Выбор порогов по `test` запрещен; зафиксируйте пороги по dev до итогового прогона.

## 5. Что прислать для итогового отчёта

Файлы `evaluation_fixed_thresholds.json`, `baseline_vs_semantic.csv`, проверенный `gold` и, после калибровки, `evaluation_calibrated.json`. По этим данным можно обоснованно сформулировать вывод, насколько semantic улучшила качество, и приложить примеры исправленных ошибок.
