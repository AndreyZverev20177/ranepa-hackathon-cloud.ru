# Архитектура Cloud Digest

Это описание **текущего исходного кода**, а не целевой инфраструктуры Cloud.ru. Проект — локальный CLI с несколькими режимами и локальная панель редактора Streamlit. Собственной БД и интегрированного интерфейса Brand Analytics нет.

## Поток данных

1. `validation.py` проверяет обычный JSON/CSV; `partner.py` переводит партнёрский JSON в общий формат (уникальные `message_id`, `published_at`, `text`, URL, сведения об источнике и необязательные метрики). `--partner-export` включает адаптер.
2. `digest.py` выбирает записи заданных суток по МСК, `preprocessing.py` готовит оригинал (`raw_text`), читаемый текст (`clean_text`), семантический текст (`semantic_text`) и проверяет текстовые варианты бренда.
3. `clustering.py` формирует группы. **Baseline:** `story_key()` с SHA-256 и особыми правилами для инцидентов. **Semantic (явный флаг):** `embeddings.py` создаёт векторы, затем кластеризация требует сходства со **всеми** участниками существующего кластера (complete link) и отсутствия явных противоречий из `event_facts.py`.
4. `scoring.py` вычисляет индивидуальный `Publication Score`. Для режимов `publication-v2` и `story-v1` справочник `source_authority.py` использует первые 25 строк `partner_data/top25_sources.json` и настраиваемые оценки из `config/publication_scoring_v2.json`. При отсутствии точного источника действуют резервные правила по домену / типу площадки.
5. `story_scoring.py` берёт лучшую публикацию сюжета и ограниченные бонусы за разные источники, дополнительную оценочную аудиторию, авторитетные домены и новые фактические **сигналы**. Дубликаты канала не увеличивают охват повторно. Противоречия ставят отметку на проверку.
6. `digest.py` выбирает до `top_n` сюжетов. Для `story-v1` модуль `story_view.py` добавляет `story_card`: основной источник, публикации в хронологическом порядке, раскладка баллов, спорные факты, признаки редакторской проверки. Запись JSON и TXT выполняет `cli.py`.

7. `ui/app.py` открывает локальную Streamlit-панель и может запускать CLI для формирования дайджеста. `editor_review.py` хранит редакторские решения в отдельном JSON-файле; оригинальная выгрузка BA, кластеры и оценки модели **не меняются**.

## Модули и точки запуска

| Модуль | Назначение |
|---|---|
| `cli.py`, `__main__.py` | Основная команда `python -m cloud_digest` |
| `core.py` | Совместимые реэкспорты прежних функций |
| `validation.py`, `partner.py` | Проверка данных и адаптер выгрузки |
| `preprocessing.py` | Очистка, выделение текста, определение упоминаний |
| `embeddings.py`, `embedding_cli.py` | ML-векторы, пакетная обработка, кэш, экспорт |
| `clustering.py`, `event_facts.py` | Сюжетные кластеры, пороги, проверки конфликтов |
| `scoring.py`, `source_authority.py` | Publication Score, 25 источников и эвристики |
| `story_scoring.py`, `story_view.py` | Story Score и представление сюжетов |
| `digest.py` | Оркестрация отбора/группировки/ранжирования |
| `candidate_cli.py`, `internet_candidates.py` | Отдельный отчёт по RSS-кандидатам на проверку |
| `evaluation.py`, `evaluate_cli.py` | Метрики качества, gold, выбор порогов |
| `io_utils.py`, `config.py` | Общие операции записи и константы |
| `editor_review.py`, `ui/app.py` | Локальные правки редактора и панель Streamlit |

## Версии алгоритмов

| Режим | Работа | Ограничение |
|---|---|---|
| `--scoring baseline` | Правила +40 негатив, +30 кризис, +20 аудитория, +10 просмотры | Простая шкала, дефолт в CLI |
| `--scoring publication-v2` | Отдельные публикации, авторитетность и плавные бонусы | Настройки не откалиброваны на редакторском эталоне |
| `--scoring story-v1` | Общий приоритет, хронология, история сильных репостов | Это прокси воздействия, а не замер уникального охвата |
| `--clustering baseline` | Хеши и словарь инцидентов | Разные сбои одного дня могут ошибочно объединяться; пересказы разными словами — разделяться |
| `--clustering semantic` | Embeddings, пороги, complete link, конфликтные признаки | Зависит от выбранной модели; точность на полном golden set не подтверждена |

Пороги семантики по умолчанию: `high=0.88`, `low=0.78`. Пара с `low <= sim < high` — кандидат на проверку, а не автоматическое объединение. Сходство `>= high` также требует совместимости фактов. `event_facts.py` ищет явные противоречия по типу события, периоду, сервису и времени; **не подтверждает правдивость утверждений**.

## Конфигурация, хранение и сеть

- `config/publication_scoring_v2.json` — веса индивидуального скоринга, экспертные оценки 25 площадок и резервные правила.
- `config/story_scoring_v1.json` — ограниченные бонусы за распространение и новые сигналы.
- `partner_data/top25_sources.json` — исходная партнёрская таблица; `media_weight` не является оценкой достоверности.
- `artifacts/embedding_cache` — по умолчанию кэш векторов; зависит от модели и версии. Содержание кэша не предназначено для Git.
- `results/` — рекомендуемый каталог новых дайджестов. `partner_results/` в архиве — исторические результаты; не перезаписывай их без необходимости.
- Основной CLI работает **офлайн** после установки зависимостей и скачивания модели (если она используется). `candidate_cli --internet` делает сетевые RSS-запросы **по явному флагу**; результаты не добавляются автоматически в основной скоринг.

## Ограничения текущей архитектуры

- Пакетная обработка по файлам, не потоковый ingestion; нет БД, API, редакторских ролей и очереди задач. Streamlit-панель работает только локально и записывает правки в JSON.
- Семантическая кластеризация сравнивает кандидатов с участниками групп, без векторного индекса: масштабирование на десятки тысяч сообщений требует отдельной работы.
- JSON/TXT основного CLI записываются последовательно; при сбое не гарантирована атомарная пара результатов.
- Нет достоверных данных о пересечении аудитории разных СМИ или о реальной вовлечённости; `Story Score` является управляемой эвристикой.
- Риск, тональность и новизна фактов проверяются простыми правилами; предполагают человека в контуре.

Будущая архитектура production-MVP: защищённый приём выгрузки/коннектор BA → очередь → нормализация → хранилище сырья и сюжетов → ML/правила → редакторская панель → публикация дайджеста → наблюдаемость. Это **план**, а не реализованные сервисы: см. [ROADMAP](ROADMAP.md).
