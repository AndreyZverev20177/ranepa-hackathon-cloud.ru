# Требования к обезличенному датасету и доработке

Основание: `Analysis.md`, `profile.json`, локальный baseline `cloud_digest/core.py`. Ниже разделены фактические проблемы и предлагаемые требования. Эти требования не являются подтвержденным договором с компанией.

## Контракт поставки компании

| ID | Требование | Критерий приемки |
|---|---|---|
| DR-01 | Manifest: версия схемы, период и timezone, происхождение, разрешенные способы использования, метод очистки, версия словаря, SHA256 файлов | Все поля manifest заполнены; хеш каждого файла воспроизводится |
| DR-02 | Стабильный непрямой идентификатор сообщения для raw, labels и кластеров | Нет повторов ID внутри raw; каждый ID labels и cluster assignments существует в raw; таблица соответствия реальным ID остается у владельца |
| DR-03 | Время ISO 8601 с offset либо Unix seconds с явной единицей | Все времена разбираются; отбор суток проверен на границе 21:00 UTC; UTC и МСК не смешиваются |
| DR-04 | Текст и заголовок передаются отдельно; правила очистки и удаления разметки документируются | Пустые text явно учитываются; title fallback помечен; полностью пустые записи не теряются молча |
| DR-05 | Источник имеет стабильный псевдоним и source_type | Ключ `(source_id, source_type)` уникален в справочнике; все внешние веса имеют версию и происхождение |
| DR-06 | Метрики — неотрицательные числа, null означает неизвестно; единицы и смысл нуля описаны | Нет bool, NaN, Infinity, отрицательных или дробных счетчиков; пустые views не превращаются в ноль |
| DR-07 | Метки поставляются отдельно от признаков | Предсказатель не читает sentiment_correct, rank, importance_score, summary, action, confidence, cluster labels или human_review_needed из golden |
| DR-08 | Протокол разметки и выбранная область оценки | Определены классы, инструкции, авторы/арбитраж, разрешение расхождений, случайный/стратифицированный отбор и support; неразмеченные строки не трактуются как negative |
| DR-09 | Для независимой приемки — закрытый holdout из другого периода с контролем дублей | Зафиксирован split до настройки; near-duplicate/story-группы не пересекают train/dev/test; метки test не использованы для весов/порогов |
| DR-10 | Для суточного ранжирования и кластеризации — полная разметка оцениваемых суток | Есть relevance всех кандидатов, суточный порядок/важность, assignment каждой строки кластеру; 30 представителей шести дней недостаточно |
| DR-11 | Обезличивание структурированных и свободных полей | Удалены/заменены author fullname/url/hash, возраст, точная география, реальные URL/ID, контакты и персональные фрагменты текста; повторные сущности получают одинаковые псевдонимы; словарь восстановления не передается |
| DR-12 | Проверка после обезличивания | Автопоиск URL/email/телефонов и ручная проверка рискованных текстов; исключения одобрены владельцем; сохранены брендовые признаки и целевые метки либо отмечено изменение задачи |

Открытый сторонний датасет допускается для отдельной разработки, если указаны источник и условия использования. Его domain shift, язык, классы и период описываются; результаты не подменяют проверку на данных компании. В текущем запуске сторонние данные не загружались.

## Минимальная карта преобразования исходной выгрузки

| Raw | Каноническое поле | Правило |
|---|---|---|
| id | message_id | Целое ID преобразовать в строку; bool и дубликаты отклонять |
| timeCreate | published_at | Unix seconds в UTC-aware ISO 8601; МСК использовать для отчетных суток |
| hub / hubtype | source_name / source_type | Сохранить пару; не объединять разные типы по одному имени |
| url | url | Валидировать HTTP(S); хранить только локально; синтетические URL в тестах |
| text / title | text | Предпочитать непустой text; если пуст, использовать title с диагностикой fallback; оба пусты — явная ошибка либо отдельный quarantine с количеством |
| audienceCount | audience | Неотрицательное целое; не суммировать со справочником источников |
| viewsCount | views | Пустая строка → null; валидное целое сохранить |
| likesCount/commentsCount/repostsCount | likes/comments/reposts | Неотрицательные целые; неверный тип диагностировать |
| toneMark | ba_sentiment | -1 → negative, 0 → neutral, 1 → positive; неизвестное значение отклонять |
| authorObject/география/служебные поля | Не нужны для минимального ранжирования | Не переносить в публикуемые файлы; не использовать как скрытые признаки |

Если поддерживается golden CSV как источник меток, целые float-представления счетчиков допустимо нормализовать только при точном целом значении. CSV пустота равна null. При импорте labels проверять schema, ID и допустимые классы; запретить NaN/Infinity.

## AC разработки текущего запуска

| ID | Изменение | Проверяемый результат |
|---|---|---|
| AC-D01 | Отдельный явный режим импорта BA либо однозначное определение формата | Существующие канонические JSON/CSV и синтетические тесты работают без изменений; raw 510 строк читается без предварительной ручной правки |
| AC-D02 | Пропуски и fallback | Все 5 пустых text обработаны через непустой title и учтены; 316 пустых views остаются неизвестными; ни одна строка не исчезает без счетчика/причины |
| AC-D03 | Время | Полный период обрабатывается, суточные входные счетчики МСК равны 137/97/61/24/22/169; синтетический тест проверяет границы суток |
| AC-D04 | Словарь как конфигурация | Загружаются 6 групп и minus_words, повторные casefold-шаблоны не меняют результат; значения не исполняются; есть тесты прямого/исторического/косвенного совпадения, границ и неоднозначности |
| AC-D05 | Справочник источников | Ключ включает source и source_type; JSON/CSV дают одинаковый эффект; дубликат пары отклоняется; media_weight конечный в [0;1], отдельный объяснимый вклад и fallback для отсутствующего источника |
| AC-D06 | Честная оценка | Golden отделен от input; все 30 ID проверены; relevance TP/FP/FN/TN и support, тональность на 26 relevant, отсутствие класса и нулевой знаменатель отражены явно |
| AC-D07 | Защита от leakage | Изменение golden sentiment/rank/summary/action не меняет предсказания; предсказывается raw text, а не отредактированный golden text; BA tone остается входом с явным происхождением |
| AC-D08 | Ограничения метрик | Отчет обозначен development evaluation, указаны 30/510 размеченных, непокрытые классы, timezone и расхождения текста; нет ложного качества кластеризации/суточного ranking/production holdout |
| AC-D09 | Некорректный ввод | Синтетические тесты: повтор ID/пары источников, отрицательный/дробный/bool счетчик, NaN/Infinity, ошибочное время, пустой текст и заголовок, отсутствующая метка; ошибка не раскрывает содержимое записи |
| AC-D10 | Прежние гарантии | Top-N не больше 30; итоговые карточки и причины детерминированы; риски вне top-N не исчезают; резюме не удлиняется вымышленными фактами |
| AC-D11 | Публикационный набор | В Git включены только код, синтетические тесты, инструкции и агрегаты; raw/golden/словарь компании/top25/построчные результаты отсутствуют; gitignore и проверка diff подтверждают это |
| AC-D12 | Воспроизведение | Сохранены команды, версии и логи type-check, build/compile, tests, реального прогона всех суток и оценки; повторный запуск дает те же агрегаты |

Выбор формулы вклада `media_weight`, приоритет категорий и эвристики контекста документирует разработчик как допущения. Отсутствие доказательства эффективности этих правил не препятствует их проверяемой реализации, но запрещает выдавать их за подтвержденное улучшение бизнеса.

## Что остается для компании и эксперимента

Нужно подтвердить источник/авторов golden, timezone, причины трех расхождений text и четырех views, фильтр и период top25, формулу media_weight. Требуется новая независимая размеченная выборка, включая косвенные упоминания, негатив, кризисные дни и нерелевантные совпадения. Исходный кейс ожидает golden 80–120 и три режима суток: 80–200 / 400–900 / 300–700 записей. Нынешний набор этим ожиданиям не соответствует; тихий, шумный и кризисный статус не размечен.

Кейс задает ориентиры сильного решения, **не формальный pass/fail**: precision привязки ≥0.90, recall кризисных сюжетов 1.00, точность тональности ≥0.80, не менее 7 карточек команды в эталонном top-10. Текущая разметка позволяет лишь предварительное сравнение первых и третьих показателей на малой выборке. Кризис и суточный эталонный top-10 не размечены. Точный объем независимой приемки и обязательные пороги согласовать по стоимости ошибок; имеющиеся 30 строк не обосновывают SLA.

Предлагаемый эксперимент: PR-редактор обрабатывает одинаково отобранные независимые дни вручную и с ассистентом; порядок дней рандомизируется, дубли разделяются по сюжетам. Измерять медиану времени редактора на сутки, долю пропущенных важных упоминаний по независимой разметке, долю исправленных карточек. Предлагаемый, не согласованный порог пилота: снижение медианного времени не менее 20% при отсутствии ухудшения recall важных упоминаний относительно ручного baseline. Требуются реальные замеры времени и разметка; текущий набор не содержит этих исходов.
