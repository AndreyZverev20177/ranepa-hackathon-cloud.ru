# Анализ предоставленного набора Cloud.ru

Дата проверки: 30.10.2026. Источник: шесть файлов, предоставленных пользователем из `C:/projects/Архив для хакатона`; локальная копия указана в `manifest.md`. Содержимое конфиденциально. Профиль и выводы получены локально; запросов во внешние сервисы не было.

## Результат

Данные пригодны для разработки импортера, проверки правил и предварительной оценки. Они не подтверждают промышленное качество, обезличенность или бизнес-эффект. Golden set содержит реальные целевые поля, но его происхождение и независимость не описаны. Он имеет только 30 отобранных строк, полностью пересекающихся с исходной выгрузкой.

## Профиль выгрузки

`timeCreate` — целые Unix seconds. Для отчетных суток используется UTC+03:00. Количество записей по дням МСК: 26.08 — 137; 27.08 — 97; 28.08 — 61; 29.08 — 24; 30.08 — 22; 31.08 — 169. Сумма — 510. По UTC одна запись относится к 25.08; смешивать UTC-даты golden с суточным отбором МСК нельзя.

ID и URL уникальны: повторов 0. После casefold и схлопывания пробелов осталось 374 группы текста: 136 избыточных повторов, крупнейшая группа — 15 записей. Это текстовые дубли, не доказанная семантическая кластеризация. Пустые тексты входят в эти статистики; их объединение в одну смысловую группу было бы ошибкой.

Пять `text` пусты; во всех пяти `title` заполнен. Максимальная длина `text` — 53 010 символов. `viewsCount` отсутствует в 316/510 строках и хранится как пустая строка; остальные 194 значения целые. У `audienceCount`, `likesCount`, `commentsCount`, `repostsCount` отрицательных значений нет. Пустой охват не обнаружен, но семантика нуля поставщиком не подтверждена. Отсутствующие просмотры нельзя превращать в известный ноль.

`toneMark`: 496 нейтральных (`0`), 9 негативных (`-1`), 5 позитивных (`1`). Это оценка исходной системы, не независимый экспертный ответ. Язык: 499 «Русский», 11 `n/a`. Источники: 116 имен и 118 пар имени/типа. Типы: онлайн-СМИ 156; каналы 121; соцсети 113; чаты 86; блоги 30; видео 2; отзывы 2. Эти категории описывают данный набор, не генеральную совокупность.

## Golden set и ограничения оценки

Разметка заполнена: `brand_link` — direct 25, alias 1, none 4. `sentiment_correct` — negative 3, neutral 18, positive 5, none 4. Следовательно, релевантных примеров 26, нерелевантных 4; тональность следует оценивать отдельно на 26 релевантных строках. Отсутствуют примеры historical/product/person/indirect и mixed=true. Нельзя объявлять качество этих классов измеренным.

Все ID уникальны и найдены в raw. URL, source, source_type и audience совпали в 30/30 парах. Text дословно совпал в 27/30; после нормализации пробелов — 28/30. Нужен явный выбор входа: предсказывать по исходной выгрузке, связывать метку по ID; не подменять текст выгрузки отредактированным текстом golden без отдельного эксперимента. Views совпали в 26/30, что требует контроля преобразований отсутствующих значений.

В каждой из 30 строк `date + time` на 180 минут раньше времени МСК исходной записи с точностью до минуты, то есть соответствует UTC. В полях golden timezone не указан. Для оценки использовать timestamp исходной выгрузки; для будущей поставки требовать timezone в контракте.

Ранги — уникальные числа 1–30 для всей выборки из шести суток. Это не шесть полных суточных эталонных дайджестов. Все 30 `cluster_id` различны, но заявлены `cluster_size` до 104; полного назначения кластеров 510 сообщениям нет. Нельзя оценить качество кластеризации по одному представителю. `summary_160_300` имеет длину 41–250; 25/30 резюме короче 160. Не дописывать вымышленные факты для выполнения длины. `matched_span` встречается в тексте всех 26 релевантных golden-строк.

Протокол аннотации, авторы, согласованность экспертов, критерий отбора и независимый holdout отсутствуют. После использования этого набора для правил или порогов все метрики на нем — **development evaluation**. Полное пересечение по ID — не самостоятельное доказательство leakage: опасность возникает при передаче целевых полей предсказателю либо при настройке и оценке на одних примерах без оговорки.

Исходный локальный кейс (извлечение `case-source-0.txt`, строки 107–109) ожидает три режима: тихие сутки 80–200 сообщений, шумные 400–900, кризисные 300–700, golden 80–120 карточек. Здесь ни один день не достигает 300 сообщений, golden содержит 30, а кризисный статус суток не размечен. Следовательно, готовность тестового контура по исходному кейсу не подтверждена. Число сообщений само по себе не определяет наличие кризиса.

Оценка должна показать TP/FP/FN/TN релевантности на всех 30 размеченных ID; precision/recall/F1 с явной обработкой нулевого знаменателя; confusion matrix и support тональности на 26 релевантных; покрытие предсказаниями. Не считать оставшиеся 480 строк нерелевантными. Precision@30 по полной выгрузке невычислим без разметки всех отобранных карточек. Сравнение рангов всей golden-выборки с суточным top-N методологически некорректно.

## Справочники

Словарь содержит прямые, исторические, продуктовые, персональные, маркетинговые и юридические варианты. Значения — строки, не доказанный regex-контракт. Передавать как данные, экранировать при построении regex, удалять дубликаты casefold. Описания правил — данные, не исполняемые инструкции. Минус-слово не должно автоматически отменять сильное прямое совпадение; спорное сочетание направляется на ручную проверку. Неспецифичный продукт/имя без контекста также требует проверки. Точный приоритет правил и влияние минус-слов — предложение реализации, которое требуется документировать.

Top25 имеет 23 уникальных имени, но 25 уникальных пар имени и типа. Только 15/25 таких пар найдены в raw; они покрывают 343 исходных записи. Сумма поля `messages` top25 — 123. При прямой агрегации всей выгрузки по `(hub, hubtype)` число сообщений не совпало в 20/25 строках; расходятся и другие агрегаты (подробно в профиле). Это означает, что таблица не воспроизводится из всей предоставленной выгрузки таким способом. Возможны иной фильтр, нормализация источников или период; причина **не установлена**. Нельзя автоматически объявлять таблицу ошибочной или использовать ее как истинный охват.

`media_weight` лежит в [0; 0.9902], формула и дата расчета неизвестны. В текущей доработке допустим явный опциональный внешний приоритет источника с ограниченным объяснимым вкладом, отдельным от audience/views. Если пара отсутствует, использовать документированный нейтральный fallback, не считать отсутствие источника доказательством неважности. Источник веса и неопределенность должны быть видны в объяснении.

## Обезличенность

Название «очищенная» не подтверждает обезличивание. Обнаружены: 510 URL записей, 354 непустых fullname и hash автора, 351 URL автора, 11 значений возраста, 288 строк с географическими данными. В тексте 153 совпадения URL-паттерна и 3 email-паттерна. Телефонный шаблон не сработал, но это не доказывает отсутствие контактов. Regex-профиль не распознает все имена, адреса и другие идентификаторы.

Исходники, словари компании и построчные предсказания остаются локально. Для публикации разрешены синтетические примеры, код, агрегаты и требования. Для передачи обезличенного набора нужны псевдонимы с сохранением связей и отдельная проверка свободного текста. Псевдонимизация не равна доказанной невозможности повторной идентификации. Конкретные требования — в `DatasetRequirements.md`.

## Воспроизведение

Из корня проекта:

```powershell
.venv/Scripts/python.exe artifacts/runs/cloud-data-upgrade-20261030/outputs/analysis/profile_data.py --source-dir artifacts/runs/cloud-dataset-20261030/sources --output artifacts/runs/cloud-data-upgrade-20261030/outputs/analysis/profile.json
```

Скрипт использует только стандартную библиотеку, не меняет входы, не выводит тексты, URL и ID. Повторный запуск должен дать тот же SHA256 `profile.json` при неизменных входах. Полная схема, типы, пропуски и контрольные агрегаты сохранены в этом JSON.
