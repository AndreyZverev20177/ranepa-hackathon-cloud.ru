# Cloud Digest — локальная панель редактора

## Назначение

`ui/app.py` — **не замена Brand Analytics**, а пользовательский контур Cloud Digest. Он читает готовый дайджест движка, показывает одну карточку на сюжет, историю источников, Story Score и очередь на проверку. Редактор может подтвердить/исключить сюжет, исправить отображаемую тональность, связь с брендом и выжимку, сохранить заметку или запрос на исправление кластера.

### Где данные и где правки

```text
Brand Analytics → JSON-выгрузка в partner_data/
                             │
                             ▼
                 cloud_digest.cli (существующий движок)
          preprocessing → clustering → scoring → story_view
                             │
                             ▼
                  results/ui/.../digest-*.json
                             │
                             ▼
                   ui/app.py (Streamlit)
                             │
                     редакторские решения
                             ▼
                 artifacts/editor_reviews.json
                             │
                             ▼
            editorial-digest-YYYY-MM-DD.json (скачивание)
```

### Установка в Windows CMD

Из **корня репозитория**, где расположен `pyproject.toml`:

```cmd
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[ui]"
RUN_DASHBOARD_WINDOWS.bat
```

Открой в браузере `http://127.0.0.1:8501`, если страница не открылась автоматически. Сервер намеренно слушает только localhost, доступ из интернета не включён.

Для режима semantic (нужна модель эмбеддингов, при первом запуске скачиваются веса):

```cmd
.\.venv\Scripts\python.exe -m pip install -e ".[ui,embeddings]"
RUN_DASHBOARD_WINDOWS.bat
```

Если получишь `No module named streamlit` — `pip` устанавливал зависимости не в тот Python: используй путь `.venv\Scripts\python.exe` в обеих командах.

### Использование

1. В боковой панели открой «Сформировать новый дайджест». Загрузить можно **свой исходный JSON Brand Analytics** или **нормализованный JSON/CSV Cloud Digest**, либо выбрать локальную выгрузку из `partner_data/`. Затем укажи дату, `story-v1` и нажми **Обработать выгрузку**.
2. Для быстрого первого запуска оставь семантическую кластеризацию выключенной: так работает Story Score с baseline-группировкой без скачивания модели. После установки ML extra переключай режим embeddings, чтобы сравнить результаты.
3. После обработки новая карточка откроется автоматически. Нажми **Скачать всё ZIP** над лентой, чтобы получить JSON и TXT одним файлом в браузерные «Загрузки». Результаты также автоматически лежат в `results/ui/`.
4. Выбери сюжет в ленте, посмотри разбивку баллов и историю распространения.
5. Во вкладке **Правка редактора** назначь статус, тональность/связь с брендом и, при необходимости, свой текст. Нажми **Сохранить решение**.
6. Скачай **редакторский JSON**. В нём есть решения редактора, исключённые сюжеты и первоначальные баллы модели.

Можно также загрузить ранее сформированный `digest-*.json` через загрузчик файла — без запуска движка.

### Важно для демонстрации и интеграции

- Панель использует реальные результаты **тех же функций**, что и CLI. Дополнительную формулу скоринга она не реализует.
- При исправлении тональности **Story Score не пересчитывается автоматически**: это отдельное редакторское решение, которое сохраняется в экспорте. Запросы на разделение/объединение кластеров тоже **не изменяют** основной граф сюжетов; нужны новая версия движка и пересчёт.
- Исходный JSON Brand Analytics **не меняется**. Файл `artifacts/editor_reviews.json` — локальный журнал **одного редактора**, не база для многопользовательской работы.
- Прямого подключения к API BA, записи в BA, авторизации/ролей и облачного хостинга **пока нет**. Для продуктивной интеграции нужны права на API, контракт на передачу сообщений, связывание `message_id`, механизм обратной записи, а затем очередь и журнал правок в БД.
- Нельзя утверждать, что показанная аудитория — фактический уникальный охват. В Story Score это ограниченный прокси.
- Не публикуй реальные выгрузки, редакторский журнал и результаты с внутренними материалами в публичном репозитории.

### Что потребуется для полноценной интеграции с BA

1. Согласовать доступный API и формат Brand Analytics; проверить, какие поля можно **читать** и **записывать**.
2. Заменить пакетную загрузку JSON адаптером инкрементального получения сообщений, сохраняя исходный `message_id`/URL.
3. Хранить сюжеты и редакторские правки в БД с пользователем и историей изменения.
4. После принятой редакторской правки **пересчитать** затронутый сюжет и обновить результат через реально разрешённый механизм BA или экспорт/внешнюю отчётность.
5. Добавить дедупликацию по времени между выгрузками, мониторинг ошибок, журнал API и разграничение доступа.


### Собственные датасеты и скачивание результатов (UI 1.1)

- Поле **«Загрузить готовый дайджест (.json)»** предназначено только для результатов `digest-*.json`.
- Поле **«Загрузить свой датасет BA / Cloud Digest (.json, .csv)»** предназначено для исходных публикаций. Поддерживаются исходная JSON-выгрузка BA, нормализованный JSON-массив и нормализованный CSV Cloud Digest. Произвольные колонки не распознаются без адаптера.
- После кнопки «Обработать выгрузку» новая обработка становится активной даже при ранее загруженном дайджесте.
- Созданные файлы сохраняются в `results/ui/<режим>/<дата>/<скоринг>/<хеш-файла>/`, а загруженные исходники — в `results/ui/uploads/`. Это защищает результаты разных датасетов от перезаписи.
- Чтобы получить готовые файлы в браузерную папку «Загрузки», нажми **«Скачать JSON»**, **«Скачать TXT»** или **«Скачать всё ZIP»**. Файлы на диске проекта создаются без дополнительных действий.
